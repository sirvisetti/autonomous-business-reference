Optional binding

Reference binding

The standard keeps business meaning and governance transport-neutral. ABR uses a tiny HTTP binding so adopters can experiment with canonical business operations without making HTTP, an API gateway or any specific enforcement technology part of the standard.

Discover

GET https://abr.sirvisetti.com/capabilities

Describe

GET https://abr.sirvisetti.com/capabilities/procurement.purchase-order.submit

Invoke

POST https://abr.sirvisetti.com/capabilities
Content-Type: application/json

{
  "abcs": "0.2",
  "capability": "procurement.purchase-order.submit",
  "requestId": "demo-001",
  "payload": { ...canonical Purchase Order... }
}

The governed boundary is above transport

Whether the request originated from an autonomous agent, workflow, application or person does not change the business operation. The reference evaluates canonical state and representative business rules before allowing the operation to produce its business effect.

Non-normative: ABR demonstrates the pattern. The current normative contracts remain in the specification; broader authority, delegation, approval, policy and accountability semantics are being developed as the next governance layer of the standard.

Reference behavior

Purchase-order submission requires a draft order with valid lines; journal posting requires a draft balanced entry; leave submission requires a draft request with a valid date range. Rejected requests return an explicit business outcome instead of silently performing an invalid effect.

OpenAPI

The OpenAPI document describes only this reference transport binding. It does not define the business standard or its governance model.
